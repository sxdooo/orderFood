## Why

社区或小规模餐饮场景下，卖家需要提前发布多日菜单、按天截单并集中配送，买家则希望便捷预订次日餐食并与卖家沟通。现有通用外卖平台流程复杂、成本高，不适合「今日订、明日送」的轻量订饭模式。我们需要从零构建一套面向微信生态的订饭小程序，覆盖菜单发布、截单、订单管理与配送路线规划等核心闭环。

## What Changes

- 新建订饭微信小程序（Taro + React），支持买家与卖家两种角色
- 新建 Go 后端 API 服务，提供菜单、订单、截单、对话、路线规划等能力
- 新建数据存储层（MySQL 为主库 + Redis 缓存/会话），部署至阿里云 ECS
- 卖家可按配送日期提前发布/编辑菜单（草稿、已发布、已过期状态）
- 买家首次登录引导填写默认配送信息（地址、联系人、电话），后续下单自动带入、可单次覆盖
- 买家可在「我的」页面管理默认配送信息；历史订单保留下单时快照
- 卖家订单详情展示买家地址、双方距离、地图双点定位；支持退单（必填原因、可选备注）并通知买家
- 卖家可为「下单日」设置截单时间，到期后自动停止接单
- 卖家按配送日期查看订单列表、订单详情及当日销售统计
- 截单后系统根据订单地址调用地图 API 计算最佳配送路线并在前端展示
- 每个订单支持买卖双方文本/图片对话
- 买家下单后通过微信支付完成付款，支付成功后订单进入待确认流程

## Capabilities

### New Capabilities

- `user-auth`: 微信 OpenID 登录、用户角色（买家/卖家）、卖家认证与权限
- `buyer-profile`: 买家默认配送信息（首次引导、我的页面管理、下单自动带入）
- `menu-management`: 按配送日期创建/编辑/发布菜单，菜品 CRUD 与状态管理
- `order-placement`: 买家浏览明日菜单、购物车、提交订单及订单状态流转
- `cutoff-control`: 卖家设置下单日截单时间，定时任务自动截止接单
- `order-management`: 卖家按配送日期查看订单、统计销量、订单详情（含距离/地图）、退单
- `delivery-routing`: 基于订单地址集合调用地图 API 计算最优配送路线并展示
- `order-chat`: 订单维度轻量 IM，支持文本/图片消息及历史记录
- `wechat-pay`: 微信小程序 JSAPI 支付、支付回调、退款

### Modified Capabilities

（无，本项目为全新构建）

## Impact

- **前端**：新建 Taro + React 微信小程序项目，含买家端与卖家端页面/组件
- **后端**：新建 Go 服务（REST API），模块含用户、菜单、订单、截单、对话、路线规划
- **数据层**：MySQL 存储核心业务数据；Redis 用于会话、截单状态缓存、消息轮询等
- **第三方依赖**：微信登录 SDK、微信支付 API v3、高德地图 Web 服务 API、阿里云 OSS
- **基础设施**：阿里云 ECS 部署（前端构建产物 + Go 服务 + MySQL + Redis）
- **定时任务**：截单检测、菜单过期状态更新等后台 Job
